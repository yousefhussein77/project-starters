# Roadmap

This roadmap keeps growth deliberate. The priority is to strengthen the library foundation before expanding the number of starters.

## Now

- keep root documentation aligned with the actual repository contents
- use `STARTER_SPEC.md` as the baseline review contract for all starter updates
- keep `reusable-design-system-starter` maintained as the reference example for documentation quality
- ship lightweight previews or examples where they help new adopters understand a starter faster
- improve clarity without adding tooling or restructuring the repository aggressively

## Next

- review each starter update against README quality, scope clarity, and adoption guidance
- tighten the criteria for moving a starter from `draft` to `usable`
- keep preview pages and templates consistent with the reusable assets they demonstrate
- improve cross-linking between root docs and starter-level docs
- document a simple repeatable review flow for promoting starters and keeping them current

## Later

- add new starters only after the documentation and quality baseline stays stable
- expand into additional starter categories such as admin, dashboard, or workflow foundations
- add richer comparison guidance once multiple starter types exist
- consider optional metadata or starter indexes only if library size makes discovery harder
- evaluate whether lightweight validation checks are worth adding after the library grows beyond a small curated set
