# Roadmap

This roadmap keeps growth deliberate. The priority is to strengthen the library foundation before expanding the number of starters.

## Now

- standardize root-level documentation for the repository
- define a clear contract for every starter through `STARTER_SPEC.md`
- make `reusable-design-system-starter` the first documented reference starter
- improve starter-level docs so adoption is faster for a new developer
- keep repository structure simple and scalable without heavy reorganization

## Next

- review each existing starter against the shared spec as more starters are added
- add lightweight previews, examples, or screenshots where they reduce ambiguity
- tighten starter status definitions and quality expectations
- improve consistency of folder naming and documentation layout across starters
- document a repeatable process for promoting a starter from `draft` to `usable`

## Later

- add new starters only after the documentation baseline remains stable
- expand the library into additional starter categories such as admin, dashboard, or workflow foundations
- create richer comparison guidance so teams can choose the right starter faster
- add optional starter indexes or metadata only if the library grows enough to justify them
- evaluate whether small validation or smoke-check workflows are worth adding after the starter set becomes larger
